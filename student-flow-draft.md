# Черновик сценария студента: выбираем офис по зоне доступности

Сценарий относится к лекции №10 о форматах данных. Это **первый проход без
ловушек**: все восемь записей корректны, каждый запрос с данными из CSV
должен успешно вернуть зону. Студент работает в браузере со Swagger UI и
картой на одной странице. Код, Jupyter Notebook и отдельный отчёт не нужны.

## История

Команда ищет офис в Чебоксарах. Есть пять адресов-кандидатов и восемь
сотрудников. Каждый должен добраться до офиса за **30 минут или меньше**
своим способом передвижения. На карте нужно получить общую область
доступности и выбрать подходящие офисы.

## Действия студента

1. Открыть страницу лабораторной, указать **фамилию, имя и группу** и нажать
   «Получить токен». Скопировать персональный токен и сохранить до конца
   занятия. Страница подключит его к Swagger автоматически и восстановит
   подключение при обновлении той же вкладки. Если вкладка закрыта, при новом
   открытии раскрыть «У меня уже есть токен», вставить сохранённое значение и
   нажать «Подключить». Токен действует 24 часа; не передавать его другим людям.
   Сессия и дальнейшие действия
   будут записаны под заявленными именем и группой. Слева находится карта и счётчик
   «Проверено 0 из 8», справа — Swagger UI с запросами и ответами.
2. Выполнить `GET /employees.csv`. Прочитать заголовки и восемь строк CSV:
   `id`, `name`, `address`, `latitude`, `longitude`, `mode`. На карте появятся
   дома сотрудников. Значение `mode` — `walk` или `bike`.
3. Выполнить `GET /offices.geojson`. Найти в ответе пять объектов `Feature`,
   их коды и адреса. Офисы появятся на карте нейтральными маркерами.
4. Выбрать одного сотрудника из CSV и выполнить `POST /isochrones`.
   Передать координаты и способ передвижения в JSON. Например,
   для Анны:

   ```json
   {
     "latitude": 56.1458246,
     "longitude": 47.2664731,
     "mode": "walk",
     "minutes": 30
   }
   ```

   Сервер найдёт сотрудника по координатам и способу передвижения. Ответ —
   объект GeoJSON `Feature` с зоной доступности. На карте обновятся
   счётчик и заштрихованная общая область. После первого запроса это зона
   одного человека; каждый следующий запрос сужает пересечение.
5. Повторить запрос для остальных семи сотрудников. Необходимые значения
   брать из их строк CSV. После каждого запроса посмотреть GeoJSON-ответ
   и изменение карты. При желании включить индивидуальный контур человека
   под картой. Повтор одного и того же запроса не добавляет сотрудника второй раз.
6. Когда счётчик покажет «8 из 8», сравнить пять офисов с итоговой
   заштрихованной областью. Выполнить `POST /decision`, передав коды
   подходящих офисов. Тело запроса имеет вид
   `{"office_ids": ["код_1", "код_2"]}`; вместо примеров строк нужно
   подставить коды, найденные в GeoJSON офисов.
7. После правильного выбора выполнить `POST /submit`. Сервис сразу вернёт
   `passed` или `not_passed` и покажет итог на странице. Если работа пока не
   зачтена, исправить решение и отправить повторно. Преподаватель получает
   уведомление о каждой новой смене результата, когда подключён Telegram.
8. Объяснить преподавателю, где использовались CSV, JSON и GeoJSON и почему
   эти данные представлены по-разному.

## Как меняется карта

- `GET /employees.csv` добавляет точки проживания.
- `GET /offices.geojson` добавляет кандидатов.
- Каждый успешный `POST /isochrones` добавляет одну зону и пересчитывает
  штрихованное пересечение **уже проверенных** сотрудников.
- `POST /decision` показывает результат выбора. Ошибочный выбор не стирает
  собранные зоны; его можно исправить.
- `POST /submit` фиксирует результат сдачи. Повторная отправка того же
  результата не создаёт новую сдачу и уведомление.
- Страница не перезагружается: клиент перечитывает состояние с сервера.
  Ответы API остаются видны в Swagger UI рядом с картой.

## Автоматическая проверка в пилоте

Сервер записывает заявленные фамилию, имя и группу, запросы и их коды ответа,
получение исходных файлов, запросы зон, выбор офисов и время этих действий.
Прогресс хранится в отдельной сессии студента. Токен выдаётся только при
регистрации; в базе хранится его хэш. При `POST /submit` сервер фиксирует
результат и ставит уведомление преподавателю в очередь. Доставка в Telegram
не заменяет запись о сдаче: если сеть недоступна, запись остаётся в базе.

Контуры остаются учебным приближением. Правило решения внутри пилота
фиксировано: 30 минут, 4,5 км/ч пешком и 12 км/ч на велосипеде; время
до офисов вычислено по сети OpenStreetMap.
